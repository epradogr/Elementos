### Práctica sesión 9 UART
En esta práctica se logró establecer una comunicación por UART para interactuar con la Raspberry Pi Pico a través de la consola, implementando un protocolo capaz de interpretar comandos para activar o desactivar actuadores como LEDs, consultar el estado actual del sistema y obtener información relevante de ejecución.
En primer lugar, UART por sus siglas en inglés significa Universal Asynchronous Receiver Transmitter; es un protocolo de comunicación serie asíncrono entre dispositivos que no comparten un reloj común, en su lugar, la sincronización se logra acordando una velocidad de transmisión compartida para muestrear los datos en intervalos idénticos.
Los pines encargados de este flujo son TX (Transmit) y RX (Receive), en enlaces entre dispositivos independientes se requiere una conexión cruzada, mientras que en pruebas de validación local se realiza una conexión directa entre ambos pines del mismo microcontrolador. En el caso particular, el bloque de hardware UART0 asigna por defecto el pin GP0 para la transmisión y el pin GP1 para la recepción.
La velocidad a la que se transfieren estos datos se define mediante el baud rate o bits por segundo, fijada aquí en 9600 bps. Para garantizar que los paquetes no se corrompan, se recurre al estándar de configuración de trama 8N1, donde cada carácter se compone de un bit de inicio , 8 bits de datos útiles, sin bit de paridad para verificación de redundancia y un bit de parada, sumando un total de 10 bits transmitidos por byte físico.
Es importante distinguir entre el USB REPL y la interfaz UART por hardware. El USB REPL  es la consola interactiva provista por MicroPython a través del puerto USB hacia la computadora , utilizada para escribir código, emitir entradas con input() y ver salidas con print(). En contraste, el periférico UART0 opera directamente sobre los registros y pines físicos de la placa, gestionando buffers de hardware independientes para el transporte serie de las señales eléctricas.
Para que la información transmitida no sea una cadena ambigua de caracteres, se define un formato de trama: una convención delimitada por comas donde el primer campo representa la acción  y los siguientes corresponden al dispositivo destino y a los parámetros requeridos, agregando un fin de línea (\n) para que el receptor sepa con certeza matemática cuándo se ha completado el paquete. El protocolo maneja tres tipos de respuestas estandarizadas: ACK (Acknowledge), que notifica al emisor que la orden fue recibida, validada y ejecutada con éxito, ERR (Error), que reporta fallos específicos ante tramas desconocidas, sintaxis inválida, dispositivos inexistentes o valores fuera de rango; y STATUS,estado lógico actual de las salidas del sistema sin alterarlas.
